# Requirements & Progress

## Requirements Overview

构建「Atoms Studio」AI 应用生成器：用户输入自然语言需求，双列并行生成两种风格的单文件 HTML 应用供对比选择；配套 Agent 思维链可视化、IndexedDB 持久化、风格偏好学习、对比历史复盘、导出与分享链接，以及 atoms/openai/mock 三模式 LLM 适配器与三层代码解析降级。

## User Stories

- 作为用户，我输入一句需求即可同时得到两版不同风格的应用，直接对比后挑选更顺手的一版。
- 作为用户，我能展开底部思维链面板，看到 AI 在需求理解、技术选型、组件设计、样式方案四个阶段的推理。
- 作为用户，我保存的应用刷新后不丢失，可按名称搜索、查看历史版本、复盘当初两版的差异与选择理由。
- 作为用户，我能看到自己的风格倾向统计，并把任意应用导出为 HTML 或生成分享链接给他人预览。
- 作为用户，我能在设置里切换模型通道、填写自定义 API Key 与 Base URL，断网时仍可用离线模板演示。

## Progress Log

- 2026-08-17 处理预置模板冒烟/体检反馈的两条缺陷，结论一真一假。「添加」按钮那条是冒烟自身的误报：冒烟流程先派发一次 form submit，模板正确地把输入框清空了，紧接着遍历点击按钮时输入框已为空，模板按设计拒绝空输入不做任何改动，于是被记成「点击后页面与表单状态均无变化」。修法是在逐个点击目标前调用 `fillInputs(true)` 只补空白控件（已有值的不覆盖，避免打乱前面交互产生的状态），再取快照对比，这样「拒绝空输入」不再被误判，真正的死按钮仍能被抓出。删除按钮尺寸那条是模板真实缺陷：`.del` 只有 `padding:2px 6px`、`.x` 仅靠字号撑开，实测约 24×25px，低于可用触控标准。除了逐个校正待办/记账/看板各风格的 `.del`/`.x`/`.dot` 尺寸外，还在模板 shell 的通用 `button` 规则上补了 `min-width/min-height:36px` 兜底，覆盖看板与通用兜底模板里若干未加 class 的裸 `×` 按钮；账本表格里那颗文字按钮「删除」不套固定方格、改用横向 padding 保持行内观感。lint、生产构建与界面渲染校验均通过。
